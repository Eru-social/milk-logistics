# Молочный Мир: план доставки

Прототип для хакатона. Строит маршруты развоза по Гродно и пересчитывает их при любой правке.

## Как открыть

- Диспетчер: `index.html`
- Водитель: `driver.html` (на телефоне — по QR-коду с кнопки «QR водителя»)

Сайт выложен на GitHub Pages. Данные лежат в Supabase (проект `molochny-mir`), поэтому все открытые экраны видят одни и те же заказы, план и отметки водителей.
Если сервер недоступен, диспетчер продолжает работать сам по себе, вместо карты при отсутствии интернета показывается схема.

## Как это работает

1. Логист правит заказы, машины или правила — правка уходит в базу, программа пересчитывает план, черновик плана сохраняется в базу.
   Сначала по общему весу выбирается наименьшее число машин (загрузка не ниже 90%), остальные остаются в гараже; потом решатель строит маршруты для выбранных машин. Над маршрутами написано, почему машин столько.
   Пока данные исходные, на экране стоит эталонный план: он посчитан заранее, с запасом времени около минуты, поэтому на любом компьютере числа одинаковые.
2. Другие экраны получают правку и новый черновик сразу и показывают тот же план.
3. Логист может вручную перенести точку в другую машину и нажимает «Утвердить план».
4. Водитель видит только утверждённый маршрут своей машины и отмечает этапы. Диспетчер видит отметки сразу.
5. Если в течение дня что-то пошло не так (машина сломалась, задерживается, точка не принимает товар), логист пишет об этом в чат справа (или нажимает подсказку под полем). Программа предлагает, как перестроить оставшуюся часть дня, и объясняет словами, кто что забирает и чего это стоит. Уже сделанное не меняется. Логист выбирает вариант и утверждает, водители видят новые маршруты.

## Что где лежит

| Файл | За что отвечает |
|---|---|
| `index.html` | каркас страницы |
| `css/style.css` | оформление, все цвета заданы переменными в начале файла |
| `driver.html`, `js/driver.js`, `css/driver.css` | страница водителя |
| `js/config.js` | адрес базы Supabase и публичный ключ |
| `js/store.js` | всё общение с базой: загрузка, сохранение, подписка на изменения |
| `js/settings.js` | все правила и допущения в одном месте |
| `js/data.js` | заказы и машины из файла логистов, с координатами |
| `js/roads.js` | расстояния и время по дорогам между всеми адресами (копия таблицы из базы, для работы без интернета и для проверок) |
| `js/base-plan.js` | эталонный план на исходных данных (создаётся скриптом `tools/make-base-plan.js`) |
| `js/fleet.js` | выбор машин по весу перед построением маршрутов: минимум машин с загрузкой не ниже 90%, остальные в гараже |
| `js/solver.js` | решатель маршрутов, написан с нуля |
| `js/replan.js` | перестроение маршрутов в течение дня, написано с нуля |
| `js/changes.js` | единый формат изменений: проверка, наложение на копию данных, описание словами |
| `js/proposal.js` | предложение «было → станет» по четырём целям заказчика, кнопки «а если»; в базу — только по «Применить» |
| `js/assistant.js` | команда словами: запрос к ИИ, поиск магазина нашим кодом, карточка «Я понял так» |
| `js/chat.js` | чат с ИИ в правой колонке: фраза → «Я понял так» → «Посчитать» → «было → станет»; подсказки без ИИ. Прежний экран без чата — `index.html?old=1` |
| `tests/` | проверки расчётов и экранов кодом, запускаются через Node.js, сайту не нужны; все считают по дорогам |
| `tools/` | скрипт эталонного плана, страница `offline-files.html` (скачать supabase.js и линии эталона), копии изменений базы |
| `vendor/` | библиотеки и шрифты (см. «Сторонние части») |
| `js/base-roads.js` | линии по улицам для эталона и «плана по списку» — карта рисует их без интернета |
| `docs/ЗА-15-МИНУТ.md` | лист перед защитой: что открыть, что нажать, что делать без сети |
| `js/map.js` | карта и запасная схема |
| `js/app.js` | экран диспетчера: таблицы, показатели, события |

Если шрифты проекта почему-то не загрузятся, страницы показывают текст системным шрифтом (San Francisco на Mac и iPhone, Roboto на Android, Segoe UI на Windows).

- OpenFreeMap — бесплатные плитки карты, ключ не нужен. Без интернета вместо карты рисуется схема маршрутов.
- Данные карты и координаты адресов — © OpenStreetMap, лицензия ODbL. Подпись на карте обязательна, она стоит в правом нижнем углу.
- Расстояния и время по дорогам между всеми адресами посчитаны один раз открытым сервисом OSRM по данным OpenStreetMap и лежат в базе (таблица `road_matrix`) и в файле `js/roads.js`. Решатель считает по ним. Экран диспетчера берёт таблицу из файла (она совпадает с базой), страница водителя — из базы.
- Линии маршрутов по улицам на карте — открытый демо-сервер OSRM. Для эталонного плана и «плана по списку» линии запрошены заранее и лежат в `js/base-roads.js` (создан страницей `tools/offline-files.html`: открыть на сайте, нажать кнопку, положить файл в `js/`); остальные линии запрашиваются с сервера и запоминаются в браузере, без сервера маршрут рисуется пунктиром.
- Языковая модель для команды словами — внешний сервис (по умолчанию OpenRouter, модель baidu/ernie-5.5-flash-preview:free), подключается ключом в секретах Supabase; её код в проект не входит. Без интернета экран пишет «модель недоступна», строки заполняются вручную.

## База данных

Таблицы: `orders`, `vehicles`, `app_settings`, `plans` (черновик и утверждённый план), `driver_events` (отметки водителей), `road_matrix` (расстояния по дорогам, только чтение), `base_plan` (эталонный план, с сайта недоступна).
Демо открыто всем, у кого есть ссылка: читать и править можно, удалять нельзя. Кнопка «Сбросить демо» вызывает функцию `reset_demo()`, которая возвращает исходные данные и эталонный план черновиком.

## Проверки

Из корня проекта: `for t in tests/check-*.js; do node $t || echo ПРОВАЛ $t; done`. Серверная функция «команда словами»: `deno run tests/check-function.ts`; с настоящей моделью: `node tools/check-phrases.js` или страница `tools/check-phrases.html` на сайте (тратит 20 запросов из дневного лимита модели). После правки файлов в `supabase/functions/assistant/` функцию нужно развернуть заново: `supabase functions deploy assistant --project-ref mhdulbsrtmcdxrzeamqk --no-verify-jwt`.
Эталонный план заново: `node tools/make-base-plan.js` (около минуты), затем применить `tools/base-plan.sql` к базе и выложить `js/base-plan.js`.

Весь остальной код написан для этого проекта.
