# Контекст проекта: «Молочный Мир», маршруты доставки по Гродно

Этот файл нужен, чтобы новая сессия Claude (или другая модель) быстро поняла, что здесь происходит, зачем, кто автор и как с ним работать. Читай его целиком перед любой работой с проектом.

## Что это и зачем

- **Хакатон в Гродно**, ноябрь 2026, длится 4 дня, начался 12 ноября. Команда — первокурсники специальности «искусственный интеллект».
- **Кейс 3, заказчик ОАО «Молочный Мир»** (молочный завод, Гродно, склад на ул. Гаспадарчая, 28). Задача: автоматизация логистики доставки продукции по городу.
- Как сейчас у заказчика: маршруты «наработаны годами», логист распределяет заказы на завтра вручную. Есть 1С, из неё приходят заказы. Ожидание от команд, со слов представителя: «как минимум идея, в идеале мини-приложение».
- **Наш продукт:**
  1. экран диспетчера/логиста (`index.html`): решатель сам строит маршруты на завтра, логист смотрит, правит и утверждает;
  2. страница водителя (`driver.html`, на телефоне по QR-коду): водитель видит свой утверждённый маршрут и отмечает этапы, диспетчер видит их сразу;
  3. перестроение маршрута при форс-мажоре с понятным объяснением (кнопка «Форс-мажор», сделано 13 ноября);
  4. в планах — сценарии «а если», 3D-модели машин и объектов на карте.
- Главная идея автора: **маршрут строит и проверяет ИИ, последнее слово за логистом** (одобрить или скорректировать).

Файл от логистов (Excel): **214 доставок, 194 разных адреса (204 остановки после склейки), 63 630 кг, 16 машин** вместимостью 1,5–5 т (суммарно 64,9 т).

Правила из файла и ответы логистов:
- Время в таблице — **время выгрузки в торговом объекте**. Пустые ячейки берут время из строки выше (протягиваем вниз). Мы читаем его как «разгрузка не раньше этого часа»; у точек, где время вписано явно («важные»), — приехать в течение часа.
- Разгрузка: **в среднем 30 минут**, мелким точкам хватает **10 минут**; от веса не зависит. Несколько получателей по одному адресу — **одна остановка**. Повторы в списке — **отдельные доставки**.
- Первая машина выезжает в **5:00**. Смена водителя **8 часов**, в неё входит **загрузка на заводе (1 час)**, обед не входит.
- **Второй рейс нельзя.** Загрузка машины **не ниже 90% — жёсткое правило**; если заказов мало, машина остаётся в гараже.
- Улицы Советская, Мостовая, Замковая — **только машина 1,5 т**.
- Сейчас точки распределены по районам, в маршруте обычно 15–25 точек, **средний пробег маршрута 45 км**.
- Тоннаж приблизительный, **это день максимальной загрузки**. Данных за другие дни **не будет**.

Наши допущения (все вынесены в `js/settings.js` и во вкладку «Правила»): мелкая точка — до 100 кг; запас на пробки ×1,2 к времени по дорогам; допуск 10 минут по смене и 1% по загрузке (мелкие отклонения видны, но не считаются нарушением).

## Что получилось (на 12 ноября, вечер)

- Пробег **476 км против ~720 км сейчас (45 км × 16), то есть −34%**. «Сейчас» — оценка со слов логистов, не их реальные маршруты.
- Все 16 машин нужны: день упирается **во время, а не в тоннаж**. Шестнадцати машинам нужно 7 671 минута из 7 680 доступных; разгрузка занимает около 80% смены, езда меньше часа. Самая длинная смена 8 ч 07 мин (в допуске).
- Вывод для защиты: узкое место заказчика — **время на точке**. Если среднее 28 минут вместо 30, день сходится с запасом.

## Как устроено

Обычные файлы HTML/CSS/JavaScript без сборки и каркасов.

| Файл | За что отвечает |
|---|---|
| `index.html`, `js/app.js`, `css/style.css` | экран диспетчера |
| `driver.html`, `js/driver.js`, `css/driver.css` | страница водителя |
| `js/solver.js` | решатель маршрутов, написан с нуля, ничего не знает про экран |
| `js/replan.js` | перестроение в течение дня: снимок дня, раздача точек сломанной машины, объяснение словами |
| `tests/` | проверки кодом без браузера: `node tests/check-replan.js` и другие |
| `js/map.js` | карта (MapLibre + плитки OpenFreeMap) и запасная схема, если карты нет |
| `js/store.js` | всё общение с базой Supabase; если сервер недоступен — работа локально |
| `js/settings.js` | все правила и допущения в одном месте |
| `js/data.js` | исходные заказы и машины с координатами (запасной вариант без базы) |
| `js/config.js` | адрес Supabase и публичный ключ (его можно держать в коде) |

**Решатель** (`solver.js`): склеивает заказы в остановки → стартовый план по секторам вокруг центра → улучшение перестановками (перенос, обмен, разворот куска маршрута, обмен машин) → «встряхивание» (вынуть кучку соседних точек и вставить заново). Цена плана = минуты езды + штрафы за перегруз, переработку, опоздания, недогруз, большую машину в центре. Лимит расчёта 2,5 секунды. Расстояния и время берутся из таблицы дорог `road_matrix` (посчитана один раз сервисом OSRM по OpenStreetMap для всех 191 точки); если её нет — оценка по прямой ×1,75. Есть «план по списку» для сравнения (`naive`). `toAssignment` / `fromAssignment` — короткая запись плана для базы и пересчёт времени без перестановки, в том числе ручной перенос точки логистом.

**Перестроение в течение дня** (`replan.js` + раздел «день уже идёт» в `solver.js`). Работает только от утверждённого плана. Логист нажимает «Форс-мажор» (или «Перестроить» у сообщения водителя о проблеме), выбирает одно из трёх: машина сломалась, задержка в пути, точка не принимает товар.
- Делается **«снимок дня»** (`live`) на время происшествия: что каждая машина уже сделала (это заморожено), где и когда освободится. Машина, которая едет к точке или разгружается, сначала заканчивает эту точку. Снимок хранится вместе с планом в базе в `plans.summary.live`, структуру базы менять не пришлось.
- **Время происшествия — по плану, а не по настоящим часам** (демо показывают днём, маршруты утренние). По умолчанию берётся по отметкам водителя, если они есть, иначе середина маршрута; логист может поменять.
- **Поломка:** оставшиеся точки сломанной машины раздаются другим, каждая туда, где добавит меньше всего езды, опозданий и переработки. Груз лежит в сломанной машине, поэтому помощник сначала заезжает к ней на **перегрузку** (20 минут, настройка). Груз исправных машин между машинами не перекладывается: на дороге это невозможно. Место поломки берётся приблизительно: у ближайшей по времени точки маршрута.
- Если без переработки не обойтись, предлагается **до трёх вариантов**: «довезти всё», «переработка до 1,5 ч», «без переработки» (часть точек сегодня не доставляется). Точку из списка «не доставим» логист может вручную отдать машине.
- **Задержка:** сдвигается время, оставшиеся точки этой машины могут поменяться местами. **Точка не принимает:** вернуться через час или не доставлять сегодня.
- Выбранный вариант становится черновиком с объяснением в правой колонке; водители видят его после «Утвердить». Водитель помощника видит карточку «Сначала перегрузка», водитель сломанной машины — кто и когда приедет за грузом.
- Пока в черновике идущий день, правки заказов и правил не запускают расчёт с нуля (только пересчёт времени). «Пересчитать» строит план заново с начала дня.
- Честный вывод для защиты: в день максимальной загрузки запаса по времени нет, поэтому поломка означает либо переработку на несколько часов, либо недовоз. В обычный день (заказов меньше, есть машины в гараже) поломку закрывает резервная машина без переработки.

**Синхронизация экранов:** правка уходит в базу → экран, где правили, пересчитывает план и сохраняет черновик (`plans.draft`) → другие экраны получают правку и черновик в реальном времени и показывают тот же самый план (не пересчитывают сами, чтобы у всех было одинаково). «Утвердить план» копирует черновик в `plans.approved`, водители видят только его.

**Линии по улицам** на карте берутся с бесплатного демо-сервера OSRM по одному маршруту за раз и запоминаются в браузере. Если сервер не ответит, линия остаётся пунктиром; расчёт от этого не зависит.

## Правила работы с проектом

1. Перед изменениями прочитай нужный файл; меняй по одной вещи и проверяй.
2. Решатель проверяй кодом: каждая остановка ровно в одной машине, сумма веса сходится (63 630 кг на исходных данных).
3. После проверок на живом сайте нажимай «Сбросить демо», чтобы в базе остались исходные данные и план был не утверждён.
4. Не добавляй сборщики, каркасы и библиотеки без явной нужды; новые библиотеки — только с открытой лицензией, версию фиксируй точно.
5. Внешние сервисы (OSRM, OpenFreeMap) бесплатные и без гарантий; у всего должен быть запасной вариант, чтобы демо не падало.
6. Ключи от платных API (например, для языковой модели) нельзя класть в код сайта — только на сервер (Supabase Edge Functions).
